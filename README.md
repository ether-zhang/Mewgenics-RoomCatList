本次采用原生外观方案：侧栏入口仍是 MewUI 创建的原生 Button；表格保留现有 ImGui 虚拟列表和输入路由，按钮/下拉框保留相同 ID、命中区域、弹窗与禁用规则。排序、调房、投送、筛选条件和复查确认流程不变。背景、按钮和职业/标记图标共用原有字体图集，资源在构建/字体更新时缓存，不逐帧加载资源。未修改原始资源包或 `ui.swf`，也不依赖 FuckOffSteve 的 DLL、代码或生成资源。

0.12.0 在右上角新增 **老猫数量控制**，与新生猫筛选共用“生成方案 → 复查拟遗弃名单 → 确定处理”的流程。复查页显示预计总数、保护数量和四个繁育房的预计舒适度；下拉改为保留、其他位置或 NPC 后即时重算。手动保留导致目标未达到时显示提示，按用户确认的选择执行。

- 老猫脚本只调整五个房间中 **年龄 >1** 的猫。幼猫、箱子及其他位置的猫计入总数，但不自动调动。所有 **房子标记（`appeal`）** 的猫始终原地保留，两个脚本都不会改标、降级或淘汰；近亲拆分时只处理未受保护的亲本。
- 繁育房成年猫统一按品质重新分层：顶楼遗传 ≥48、二楼 ≥46、一楼左 ≥45。比较遗传总和、优质变异数、有无职业，最后随机；顶楼仍先比较遗传敏捷是否为7。不沿用新生2/3只名额或每次晋升2只的限制。
- 顶楼舒适度至少15；二楼两房以至少5为目标，优先平衡舒适度；一楼左至少0。舒适度采用引擎公式：家具等房间效果 + 猫咪自身房间效果 − `max(猫数−4, 0)`，房子标记和幼猫仍占用容量。达到容量后较弱成年猫流向下层，最后转战备。
- 顶楼和二楼要求无近亲；一楼左允许轻度近亲（系数 >0.1 且 ≤0.25）。坏变异、疾病、中重度近亲直接转战备筛选。保护标记优先于这些规则。
- 战备猫不回流繁育房，不限制房间舒适度。真实总和 <52 或至少两项真实值 ≤5 时进入拟遗弃名单。总量仍大于90时，继续从战备、一楼左、二楼、顶楼依次择弱淘汰；战备只比较真实总和、优质变异能力、有无职业，不比较遗传潜力。
- 总量目标是 **不超过90**。保护猫、幼猫或必要舒适度贡献使目标无法达成时，保留这些限制并提示；不会为凑数量扩大筛选范围。家具或猫咪资料在确认前后变化会拒绝或停止剩余操作。

当前新生筛选规则如下：

- 繁育房为顶楼、二楼左/右、一楼左，只筛年龄为 **1** 的小猫；一楼右用于备战，最终筛选覆盖其中所有年龄的猫咪。原有成年繁育猫仅在近亲亲本拆分时移动。
- **优质变异**仅统计好变异：纯数值效果必须有正增益且没有任何负项，`+2/-1` 不计；含功能性被动或攻击/移动替换的变异可计入。纯显示偏移不计。好突变格显示 `总数 / 优质数`。
- 出生标记为顶楼三角、二楼左方框、二楼右圆、一楼左宝剑。已有上述出生标记时保留；没有时以生成方案时所在繁育房为准。调房不会改写出生标记。
- 近亲沿用表格“轻/中/重”的标准（系数 >0.1）。同一对父母的多胎只拆一次，比较遗传总和、优质变异数量，较弱亲本下降一级；亲本已分处不同房间或不同时在繁育房时不再降级。一楼左的较弱亲本转入一楼右。近亲小猫转备战，接受最终真实属性筛选。
- 无近亲新生猫可晋升一级：二楼遗传总和 ≥48、一楼左 ≥46；**每个原始楼层最多晋升2只，单次只升一级**，二楼两房合计计算晋升名额。一楼右不参与晋升。晋升猫与上层本地小猫竞争相同的新生保留名额。
- 顶楼只留遗传总和 ≥48 的新生猫，合计最多2只；优先遗传敏捷恰为7，再比较遗传总和、优质变异数、有无职业，最后随机。其余均匀下放二楼。
- 二楼只留遗传总和 ≥46 的新生猫，每房最多3只。先按遗传总和、优质变异数、有无职业、随机选择最多6只，再尽量安排每房2只本房出生、1只对面出生，并平衡两房品质。其余下放一楼左。
- 一楼左保留遗传总和 ≥45 的新生猫，未设数量上限；其余转入备战。一楼右最终淘汰真实总和 <52，或 **至少2项真实属性 ≤5** 的猫咪。所有拟遗弃猫均进入复查表。

确认时再次核对猫咪、房间和日期；执行逐项验证原生结果。数据变化、箱子无法接收或 NPC 条件改变时停止剩余步骤，不擅自改为遗弃。打标通过游戏原有的符号字符串赋值入口完成，投送/遗弃沿用原生流程，不直接编辑存档。当前游戏会话中，已经完成且猫咪状态未变化的方案不重复执行。

## 使用

1. 启动游戏，进入家园。
2. 点击左侧按钮栏中、购物车下方的 **猫咪列表** 图标（猫头和列表横线）。
3. 未聚焦房间时显示 **全屋猫咪**；用滚轮聚焦房间后再打开，显示对应房间的名单。
4. 面板显示范围、数量及猫咪详情。滚轮上下滚动，Shift+滚轮或横向滚轮左右滚动，也可拖动两个滚动条。右上角 × 或 Esc 关闭。
5. 鼠标位于列表时操作列表；移出后可正常操作家园。拖动滚动条、面板标题或边框时，移出边界仍继续该次拖动，直到松开。
6. 面板位置和尺寸会保存在 Mod 目录的 `ui-state.ini`，关闭重开、重新启动游戏后都会保留。
7. 点击第一列的位置框，选择目的地后移送；灰色选项可悬停查看原因。菜单打开时，点击外部或按 Esc 先关闭菜单。
8. 点击父母栏进入父母表格；“返回上一级”、Esc 或手柄 B 返回原表格，并恢复排序和滚动位置。
9. 点击右上“新生猫筛选”查看拟遗弃名单，调整最左侧处理方式后点击“确定处理”。即使名单为空，打标和调房仍须点击确定。
10. 点击相邻的“老猫数量控制”生成成年猫方案，核对底部预计总数和舒适度，再确认执行。取消复查不改变任何猫咪。
11. 在“筛选设置”中修改规则并保存，然后按相应脚本生成方案。已有的投送去向记忆会继续用于复查。

查看列表和悬停说明不改变猫咪。仅在用户选择目的地或 NPC 后调用对应的原生移动/投送流程，由游戏正常处理位置、NPC 进度及保存；不直接编辑存档。
本版支持单只移送、全屋和当前房间名单、年龄/属性排序、悬浮详情，以及新生筛选和老猫数量控制的复查与批量处理。

## 文件夹式加载

Mod 本体位于游戏目录的 `mods/RoomCatList/RoomCatList.dll`。
游戏根目录的 `version.dll` 是 Mewjector 加载器，`chainloader.ini` 指定加载子文件夹中的本体。
加载器是一次性基础依赖，需要 Mewjector API v3；不需要每次另开管理器。
Mod 在游戏解析启动参数时自动注册自身资源目录，保留已有启动选项和其他 Mod 路径。
`swfs/house.swf` 从本机的原资源包生成，保留原有资源，只在 HUD 中加入按钮；原资源包不被修改。

配置示例（已有加载器配置时只添加新的条目，保留其他 Mod 的设置）：

```ini
[Chainloader]
ScanPath=mods
ScanGameDir=0
MewtatorManifest=
Enabled=1
Logging=1

[LoadOrder]
Mod1=RoomCatList\RoomCatList.dll
```

也可通过 Mewtator 启用此文件夹和 DLL 支持；避免同时加载多个副本。

## 禁用

退出游戏后，在 `chainloader.ini` 中注释掉 `Mod1=RoomCatList\RoomCatList.dll` 这一条。
如果通过 Mewtator 管理，则在管理器中停用本 Mod。下次启动时生效。
如果此加载器仅用于本 Mod，也可以将 `[Chainloader]` 的 `Enabled` 改为 `0`。

## 适配和诊断

- 构建时核对 MewUI API 的 73 个符号；启动时检查相关机器码和猫咪数据布局。签名不匹配时停用对应功能。
- 数据从当前游戏进程读取：聚焦房间、房间成员和已经加载的猫名缓存。
- 父母 ID 来自当前家谱哈希表；优先读取缓存中的姓名，历史父母未缓存时调用游戏自己的 CatDatabase 查询。按父母 ID 缓存加载尝试，切换日期或家园场景时失效，已缓存姓名改名后会随名单刷新。
- 年龄、遗传属性和疾病槽来自已加载的 CatData；真实属性和突变枚举调用游戏自身的查询函数。按猫咪数据和游戏日期缓存结果，不逐帧重新计算。读取不完整的详情显示 `—` 并排在排序末尾。
- 突变和疾病的中英效果在构建时从本机 `resources.gpak` 生成；生成的游戏文本和 SWF 不纳入 Git。
- 不直接打开或改写存档文件，不联网，不修改游戏 EXE 或资源包。
- `RoomCatList.log` 记录加载结果、房间标识、数量和读取耗时，不记录猫名。
- 加载器日志在游戏根目录的 `mod_logs/chainloader.log`。
- 原生按钮的资源注册和创建结果写入加载器日志，查找 `RoomCatList` 条目。
- 原生字体在构建时从本机游戏生成缓存；Windows 自带的 Microsoft YaHei 用于补齐罕见字符。

## 构建

需要 Visual Studio 2022 Build Tools 的 C++ x64 工具、Windows SDK、Python 3（含 Pillow），以及当前安装的游戏资源包。
运行本目录 `build.cmd`，产物在 `build/`，不会自动关闭或启动游戏。
测试通过后使用更新入口一起安装 DLL、字体缓存和侧栏资源。加载器产物是 `build/version.dll`。
运行中的 DLL 不应覆盖，请先正常退出游戏。
游戏退出后可运行 `apply-update.cmd` 安装 `build/RoomCatList.dll`、`build/assets/native-ui.ttf` 和 `build/swfs/house.swf`。更新脚本不启动或关闭游戏。
更新入口允许本次 PowerShell 进程运行本地脚本，不修改系统执行策略。复制后分别核对三个文件的 SHA256，并保留结果窗口；看到 `update VERIFIED` 表示替换成功。只重新启动游戏不会自动应用 `build/` 中的新版。
